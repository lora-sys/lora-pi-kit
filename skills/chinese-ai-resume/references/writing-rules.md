# 中文 AI 岗简历写作规则

## 用人话写技术事实

先说场景和问题，再说本人动作，最后给可解释结果。不要把“熟悉、赋能、构建、提升、全链路、从 0 到 1”等词当成果。技术名词只在它帮助说明动作或边界时出现。

| 不建议 | 改写方向 |
|---|---|
| 构建可信 Agent 平台，保障高可用 | 设计回答、证据、审批的记录链。审查未通过时，系统拒绝导出对外材料。 |
| 使用 LangGraph 和多 Agent 实现智能协同 | 用状态机固定观察、决策和执行顺序，避免模型跳过步骤或自行改写结果。 |
| 通过技术优化提升稳定性 | 处理 SSE 重复事件、取消流和终态保护，外部模型超时后进入降级状态。 |
| 具备优秀的学习能力与沟通能力 | 持续维护公开作品；在多人项目中先约定接口、消息和模块责任，再开始联调。 |

## 强制结构

每个主项目使用“公开链接 → 项目介绍 → 5 条主要工作”。项目介绍用 2 至 3 句说明对象、问题和现状。五条通常覆盖架构、决策、难点、质量和边界；如果事实不支持五条，不要编造，改为减少主项目数量或把弱项目放到其他作品。

## 事实边界

不要虚构用户数、营收、生产数据、模型效果或工具使用经历。不要把 Mock、Replay、单元测试、设计方案写成真实线上运行。说明未完成项不会减分，隐瞒边界会让整份简历失去可信度。

## 句子检查

用主动句。拆开过长句。少用冒号、破折号和叠加定语。删掉换个项目也能成立的句子。每条写完问三个问题：谁做了什么、为了解决哪件具体事、证据在哪里？
