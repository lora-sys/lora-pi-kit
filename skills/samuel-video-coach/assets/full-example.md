# 完整原创示例：我让三个 AI Agent 互相审查一个开源项目

> 示例用于演示 Skill 如何手把手输出，不是 Samuel 的原视频或台词。

## 0. 今天只做什么

1. 准备最终产品页面、两个真实 Bug、测试报告和三个 Agent 的运行录屏。
2. 先用手机录 8 段短口播，每段只说 1–3 句。
3. 录屏展示“单 Agent 说通过”和“另外 Agent 找出 Bug”的对比。
4. 补拍手点运行、等待、看到报错、停在上线按钮四个动作。
5. 生成两个 AI 过渡：一个表现“一个人变成三人审查”，一个表现“速度冲过安全刹车”。
6. 先剪口播，再盖录屏，再放补充画面，最后插 AI 过渡。

## 1. 导演总判断

这条视频不是“多 Agent 架构介绍”，而是：

> 当 AI 可以高速写代码时，谁来审查 AI，责任又应该由谁承担？

最强结果是：第一个 Agent 认为项目通过，另外两个 Agent 找出了真实问题。

不要一上来解释 Agent、模型和框架。先展示“绿灯通过”和“两个 Bug”同时存在。

## 2. 证据缺口

| 事实 | 证据 | 处理 |
|---|---|---|
| 三个 Agent 都参与了审查 | 三段运行日志或任务结果 | 必须录屏 |
| 找到了两个真实 Bug | Issue、测试失败或代码 diff | 必须展示 |
| 是否提升质量 | 只能证明本次案例 | 说“在这次项目里”，不能普遍化 |
| 花费时间 | 若没有准确记录 | 不写具体数字 |

## 3. 视频定位卡

- 平台：抖音。
- 时长：3 分钟。
- 观众：AI 开发者、独立开发者、对 Agent 感兴趣的人。
- 类型：真实实验。
- 中心问题：让 AI 审查 AI，能不能真正降低代码风险？
- 一句话承诺：你会看到三个 Agent 对同一项目给出冲突判断，以及它们究竟找出了什么。
- 最终判断：多 Agent 能扩大检查视角，但不能替人承担上线责任。

## 4. Samuel-inspired 对应

| 规律 | 使用方式 |
|---|---|
| 结果先行 | 开头先给绿色通过与两个 Bug 对切。 |
| 人的故事 | 创作者担心“写得太快但没人负责”。 |
| 动作化 | 不说“多 Agent 协作”，而说“让三个 AI 分别扮演开发者、Bug Hunter 和架构师”。 |
| 真实实验 | 同一项目、同一代码、明确角色、真实结果。 |
| 反转 | 第一个 Agent 说通过，另外两个发现问题。 |
| 个人判断 | 可以加快审查，但最终权限仍应在人。 |
| 讨论 | AI 能执行到什么权限边界？ |

## 5. 推荐标题和开头

推荐标题：

> 我让三个 AI 互相审查代码，结果它们吵起来了

推荐封面：

- 左边：绿色“PASS”；
- 右边：两个红色 Bug；
- 你在中间看向两侧；
- 大字：“到底听谁的？”

推荐开头：

> 第一个 AI 告诉我，这个项目可以上线。五分钟后，另外两个 AI 找出了两个真实 Bug。所以现在的问题不是 AI 会不会写代码，而是谁来审查 AI。

## 6. 3 分钟节拍

| 时间 | 任务 | 内容 |
|---|---|---|
| 0:00–0:10 | 结果与冲突 | PASS 与 Bug 对切，提出“谁审查 AI”。 |
| 0:10–0:30 | 人物动机 | AI 写得越来越快，我担心速度超过责任。 |
| 0:30–0:45 | 实验规则 | 同一项目，三个角色，不互相看结论。 |
| 0:45–1:30 | 进展 | Developer Agent 完成并自检，显示通过。 |
| 1:30–2:05 | 反转 | Bug Hunter 与 Architect 找到问题。 |
| 2:05–2:35 | 证明 | 展示 Bug、修复和重新测试。 |
| 2:35–2:52 | 判断 | 多 Agent 增加视角，不等于承担责任。 |
| 2:52–3:00 | 讨论 | 观众愿意给 Agent 哪一级权限。 |

## 9. AI 镜头样例

### AI-01：一个任务变成三个审查者

- 前锚点：真实手指点击运行按钮时的圆形光点。
- 后锚点：三个角色卡片上的三个圆点。
- 中文 Prompt：

```text
9:16 竖屏电影感微距过渡镜头。一根真实感手指按下一个圆形发光按钮，光点沿着三条清晰路径分裂，分别进入三个简洁、无文字的透明工作舱。隐喻是一个任务被三个独立角色审查。镜头轻微向前推进，首帧只有一个圆形光点占据画面中心，尾帧稳定停在横向排列的三个同尺寸光点，时长 2 秒。无文字、无 Logo、无水印、运动符合物理规律。
```

- 失败替代：用后期三分屏和三条线动画。

### AI-02：速度超过控制

- 前锚点：真实日志快速滚动。
- 后锚点：真实红色错误标记。
- 中文 Prompt：

```text
9:16 竖屏电影感近景，一个小型机械开发者以极快速度在透明键盘上工作，旁边的红色安全刹车杆逐渐滑出手的可触范围。画面只表达“速度超过控制”这一个隐喻。镜头横向跟随，冷色显示器光，唯一红色元素是刹车。首帧由快速向上滚动的细线填满画面，尾帧停在居中的红色圆形警示灯，时长 2 秒。无文字、无 Logo、无水印。
```

- 失败替代：真实日志 4 倍速，突然停在红色“BUT / 但是”。

## 10. 评论设计

- 共鸣：“Agent 写得越来越快，快到我们可能来不及怀疑它。”
- 支持方：愿意给更高权限，认为速度价值更大。
- 反对方：只允许读代码，责任和数据权限必须在人。
- 置顶评论：

> 视频里用的是测试项目。四级权限：①读代码 ②改代码 ③访问数据库 ④自动部署。你最多给到哪一级？下一期我按票数最高的边界继续测。
