# Resonance and Discussion System

## 1. 共鸣不是煽情

共鸣来自观众认出自己的处境：

- 收藏了很多工具，却一个也没真正用；
- 想靠 AI 提效，却花更多时间折腾配置；
- 想边旅行边工作，却一直被消息追着跑；
- 想让 Agent 自主执行，又不敢交出权限；
- 不会编程，但很想做出自己的产品；
- 看见新技术很兴奋，也担心自己被淘汰。

## 2. 共鸣句结构

`观众熟悉的行为 + 不愿承认的后果`

例如：

> 我们收藏了几十个 AI 工具，真正改变工作的，可能一个都没有。

> 很多人想要的是边旅行边工作，最后却变成走到哪里都在加班。

## 3. 讨论必须有两个合理立场

### 速度 vs 控制

- 支持：速度带来竞争优势；
- 反对：权限错误可能造成不可逆损失。

### 隐私 vs 便利

- 支持：自动读取数据节省时间；
- 反对：个人和公司数据不应交给不透明系统。

### 自由 vs 稳定

- 支持：远程和游牧生活带来自主；
- 反对：收入、时差和边界变得不稳定。

### 自动化 vs 责任

- 支持：Agent 可以承担大量执行；
- 反对：结果出错时仍然需要人负责。

## 4. 评论问题公式

`我的证据判断 + 一个真实取舍 + 一个有边界的具体问题`

例：

> 这次测试里，它把开发速度提高了很多，但我必须收回数据库权限。假如能快 80%，你愿意给 Agent 的最高权限到哪里？

## 5. 置顶评论

置顶评论不是重复 CTA，应补充：

- 一条视频没讲完的限制；
- 资料领取的真实规则；
- 观众选择题；
- 下一次实验标准；
- 纠正容易误解的事实。

例：

> 补充：视频里的数据是测试库，不是生产数据。下一期我会让三个 Agent 互相审查，大家最想先测安全、成本还是速度？

## 6. 系列承接

结尾不必强行“关注我”。可以承诺下一步实验：

- 加入第二个工具对比；
- 让三个 Agent 互相审查；
- 在真实旅行中连续使用七天；
- 让完全不懂技术的人复现；
- 测试成本、隐私或长期稳定性。

承诺必须真的准备做。

## 7. 禁止

- 伪造争议；
- 煽动职业或群体攻击；
- 把极端观点当唯一选项；
- 用虚假资料领取诱导互动；
- 把“评论区见”当作不回答中心问题的借口。
