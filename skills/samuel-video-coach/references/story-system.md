# Story System

## 1. 主角不是工具

主角是一个人想要：

- 更自由地工作；
- 更快完成产品；
- 赚到第一笔收入；
- 学会一个难东西；
- 保存一段旅程；
- 证明一个流行说法；
- 避免被技术替代；
- 获得创造和表达能力。

工具只是改变这个人的手段。

## 2. 中心问题

中心问题必须能被视频中的证据回答：

- 能不能？
- 值不值？
- 普通人能不能复现？
- 到哪一步会出问题？
- 得到自由的同时失去了什么？
- 快多少，代价多大？

避免无法回答的宏大问题，如“AI 会不会改变世界”。

## 3. 七段结构

### 1. 结果预览

让观众先看到最终产品、结果、地点或事故。

### 2. 人物动机

解释为什么是你做、为什么现在做、这件事与普通人有什么关系。

### 3. 规则或路线

用三步、三个标准或一个明确限制，让观众知道接下来如何验证。

### 4. 操作—结果—解释循环

不要连续讲理论：

`做一个动作 → 看到结果 → 解释一句 → 做下一个动作`

### 5. 中段反转

必须改变观众对前半段的理解，而不只是插一个小报错。

### 6. 最终证明

给出前后对比、数字、产品、测试或现场结果。

### 7. 判断和讨论

回答：

- 什么有效；
- 什么无效；
- 适合谁；
- 什么条件下会使用；
- 你现在相信什么；
- 观众可以争论什么。

## 4. 四种主模板

### A. 真实实验

`结果闪现 → 大家都在说的主张 → 我的测试规则 → 过程 → 翻车/代价 → 结果 → 判断`

### B. 结果教程

`成品 → 观众痛点 → 三步路线 → 每步操作和结果 → 常见坑 → 完成结果 → 谁适合`

### C. 人物旅程

`目的地或重大结果 → 为什么出发 → 过程和阻碍 → 到达 → 发生的思想变化 → 对普通人的意义`

### D. 观点故事

`强判断 → 个人经历 → 证据 → 反方观点 → 修正后的判断 → 讨论`

## 5. 开放问题

可以在前面承诺稍后回答：

- “功能做出来了，但真正的问题在最后一步。”
- “我以为贵的是模型，后来发现完全不是。”

每个主要问题必须在本视频中解决。不要永久吊胃口。

## 6. 结尾判断模板

`有效的部分 + 失败的部分 + 适合的人 + 使用条件 + 我的新判断`

例如：

> 它能把第一版从一天压到一小时，但不能替你承担上线风险。做原型非常值，处理核心数据时，我只会在完整审查后使用。
