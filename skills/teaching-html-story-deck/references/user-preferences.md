# User Preferences

These defaults were gathered through the iterative Shape Up teaching-HTML workflow.

## Narrative

- Chinese-first.
- Start with the real problem, not the product name.
- Preferred sequence:
  `问题定义 → 使用场景 → 原理 → 核心方法 → 数据流 → 架构/思维模型 → 实战 → 最后揭示 Skill/产品`.
- The product or Skill should feel like the earned conclusion, not an advertisement inserted at the beginning.
- Use a strong contradiction or tension in the first page.
- One main argument per page.
- Include practical examples and before/after transformations.

## Visual language

- High-finish, restrained, modern developer-product aesthetic.
- Near-black and white as the base.
- One fluorescent yellow-green accent.
- Fine borders, subtle panels, large editorial typography, generous spacing.
- Quiet grid, mild grain, and soft pointer glow are welcome.
- Avoid colorful template aesthetics, giant gradients, noisy glassmorphism, and generic dashboards.
- Prefer diagrams and structures over decorative stock imagery.
- Mondo-style poster thinking may influence hierarchy and framing, but teaching HTML should remain cleaner and more interactive.

## Motion

- Advanced but controlled.
- Desired qualities: precision, speed, continuity, subtle light, and restraint.
- Never imitate exact brand layouts, logos, or proprietary assets.
- Motion must explain sequence, data direction, hierarchy, progress, uncertainty, or state change.
- Useful patterns: staged reveal, animated SVG paths, subtle pulse, hover lift, page transition, overview mode.
- Avoid particle storms, strong parallax, large floating objects, or animation behind dense text.
- Respect reduced-motion settings.

## SVG and diagrams

- Generate diagrams that fit the current content.
- Useful defaults:
  - data flow;
  - architecture;
  - radial mind map;
  - 2×2 trigger matrix;
  - Hill Chart;
  - responsibility and permission graph;
  - before/after comparison;
  - evidence gate;
  - lifecycle and decision flow.
- Use inline SVG so the file remains portable.
- Labels must be readable and teachable during narration.

## Technical

- Default to one self-contained HTML file.
- No build system or external dependency.
- Must work offline.
- Include keyboard navigation and fullscreen.
- Include hidden presenter notes.
- Responsive for laptop teaching and screen recording.
- Include `prefers-reduced-motion`.
- Validate before delivery.

## Tone

- Clear, opinionated, developer-oriented.
- Avoid empty marketing language.
- Explain why a visual or mechanism exists.
- Do not invent metrics or proof.
