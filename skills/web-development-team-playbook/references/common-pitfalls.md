# 常见 Web 实现问题

在遇到视觉接缝、对比度、主题、路由、导航、查询循环、链接或选择器问题时读取本文件。按问题原因修复；不要只通过增加随机样式、延迟或重试来掩盖症状。

## SVG 波浪与分段背景露底

**症状：** 波浪、曲线或斜切分隔符之间露出上一段背景，尤其在 `overflow: hidden`、绝对定位或翻转 SVG 时形成“夹层”。

**原因：** SVG path 填充了错误一侧；通过 CSS 旋转派生相反方向时，同时翻转了填充与颜色语义；绝对定位使区块接缝无法稳定重叠。

**修复：** 为上填充和下填充分别设计明确 path，不依赖旋转；优先使用文档流中的分隔元素并以负外边距重叠前一节；分隔器的颜色对应**目标**区块背景而非来源区块。跨浏览器查看接缝，必要时用 1px 重叠消除子像素缝隙。

## 实际背景的文字对比度

**症状：** 文字在预期背景下可读，但滚动、图片、透明容器或视频显示时不可见。

**常见陷阱：** 固定透明导航在浅色内容上失去对比；绝对定位文字使用容器背景而非图片亮度判断颜色；半透明卡片让文字背景取决于下层内容。

**修复：** 问“用户此刻实际会看到文字后面是什么”。背景可能变化时，为导航切换实体表面，为图片文本加渐变遮罩，或为文本提供稳定的半透明/实色表面。不要仅靠“文字是白色”假定它可读。

## 主题变量与语义色不一致

**症状：** 切换深浅主题后出现不可见文字、卡片与前景色错配、Popover/Accent 与背景混淆。

**修复：** 让主题提供者的默认值与 CSS 变量的深/浅主题定义一致。使用语义背景时，显式配对其对应前景色，例如 `bg-card` 配 `text-card-foreground`、`bg-popover` 配 `text-popover-foreground`。在每个主题和关键背景上实际检查对比度。

## 渲染期创建不稳定查询输入

**症状：** 查询无限触发、加载状态循环或依赖变化异常。

**原因：** 在每次渲染时创建新的日期、对象或数组，并将其传入依赖引用身份的查询/Effect。

```tsx
// 不稳定：每次渲染均创建新对象
const result = useQuery({ queryKey: ["items", new Date()] })

// 稳定：初始化一次或为复杂输入创建稳定引用
const [date] = useState(() => new Date())
const result = useQuery({ queryKey: ["items", date] })
```

**修复：** 使用稳定原始值、`useState` 初始化器、`useMemo` 或将输入构建移至恰当的边界。确认目标库的实际比较规则；不要为了消除循环盲目移除依赖。

## 子页面导航死路

**症状：** 详情页、嵌套路由、错误页或管理区没有主导航、返回操作或可理解的退出路径。

**修复：** 先定义顶层布局和路由层级，再制作独立页面。为详情、嵌套流程和模态提供上下文适合的返回、关闭、面包屑或主导航。检查浏览器历史、刷新与直接访问路径。

## 嵌套锚点与链接组件

**症状：** 控制台警告、无效 DOM、事件不一致或点击区域错误。

**原因：** 在已经渲染 `<a>` 的 Link 组件中再放 `<a>`，或把锚点嵌套在锚点内。

**修复：** 阅读当前路由库 Link 的渲染行为。若 Link 自行渲染锚点，直接传递内容或使用其推荐的组合方式；不要嵌套锚点。

## Select 的空值

**症状：** 某些选择器报运行时错误、无法清空或在受控状态下异常。

**修复：** 选择库禁止空字符串值时，为“未选择”使用库要求的受控占位符状态或安全的哨兵值。每个 item 赋予有效、非空且语义明确的值。不要假设不同组件库对空值的规则相同。

## 占位功能伪装成可用

**症状：** 未实现的导航、CTA、路由或按钮看起来可操作却无真实动作，或以成功状态掩盖“即将推出”。

**修复：** 实现真实功能；若任务明确要求结构占位，则用可理解的禁用状态或真实提示说明其尚不可用，并在交付中列出。不得让草稿功能、失败请求或断开服务显示成功。

## 发现问题时的顺序

1. 复现并隔离最小条件。
2. 检查运行时状态、DOM、网络、控制台和实际视觉结果。
3. 定位状态、语义、布局或数据边界上的根因。
4. 做最小修复并运行相关验收。
5. 让严格隔离审查重新尝试寻找回归或反例。
