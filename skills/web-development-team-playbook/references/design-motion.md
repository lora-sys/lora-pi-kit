# UI、可访问性与动效标准

在新建或改造用户可见界面、设计系统、主题、布局、动效或视觉状态时读取本文件。优先遵守当前项目已有的品牌资产、组件库和设计 token；没有明确品牌规范时才按此文件做审慎的设计决定。

## 视觉与布局

选择有明确意图的设计语言：颜色、字体、阴影、圆角、密度、层级和背景应服务于内容与任务，而不是套用无差别的居中卡片模板。营销/内容页面优先采用与信息结构相符的不对称布局、清晰层级和适度质感；仪表盘/管理工具优先使用明确间距体系、克制阴影、可扫描的数据层次和稳定导航。

开始实现前，决定默认的明暗主题和全局颜色语义。通过项目已有 token 或 CSS 自定义属性管理背景、前景、边框、强调色和状态色，避免在组件中散落难以统一的硬编码值。无论采用何种组件库，都要保持相同语义色与文字色的成对关系。

不要假设父容器背景就是用户看到的背景。固定透明导航、图片上的绝对定位文本、半透明面板、视频背景和滚动时变化的区域都必须按**实际渲染背景**验证文字对比度。背景可变时，使用可见表面、渐变遮罩或随滚动切换的实体背景来保证对比度。

## 响应式与导航

采用移动优先布局，并在真实窄屏与宽屏视口中验证。不要只缩小桌面布局：重审阅读顺序、点击目标、表格策略、菜单密度、表单键盘、Canvas/3D 的降级和图片裁切。

先定义全局布局与导航逃生路径，再实现子页面。嵌套路由、详情页、模态流程和管理区必须有清楚的返回、关闭、面包屑或主导航路径。不得创建用户无法离开的页面。链接组件自身输出锚点时，不得再嵌套 `<a>`。

保留可见焦点指示、键盘可达性和逻辑 Tab 顺序。图标按钮应有可理解的名称；仅颜色不能承载唯一状态信息；加载、错误、成功、空状态和不可用状态均应可被感知且不误导。

## 动效

动效属于实现的一部分，不是最后的装饰。先决定是否应该动：键盘快捷键等即时操作不得加动画；高频 hover 和列表导航应极轻；对话框、抽屉、提示和首次引导可使用更丰富但克制的运动。

| 场景 | 默认建议 | 禁止或警惕 |
|---|---|---|
| 按钮按下 | 约 100–160ms，使用轻微缩放等真实反馈 | 不要让点击无响应或出现过长回弹。 |
| Tooltip | 约 125–200ms | 不要让提示阻碍键盘或遮挡目标。 |
| 下拉/Popover | 约 150–250ms，从触发点方向展开 | 不要使用不明来源的居中缩放。 |
| Modal/Drawer | 约 200–500ms | 不要延迟可操作内容或使关闭变慢。 |
| 分组进入 | 每项 30–80ms 错峰 | 不要把所有元素同时弹入。 |

默认使用快速、明确的自定义缓动，例如进入/退出可使用 `cubic-bezier(0.23, 1, 0.32, 1)`，移动/变形可使用 `cubic-bezier(0.77, 0, 0.175, 1)`。避免 UI 动效使用纯 `ease-in`，它容易显得迟滞。尽量只动 `transform` 与 `opacity`；避免为装饰而频繁动尺寸、边距、定位或布局属性。

不要从 `scale(0)` 开始出现元素；必要时可从约 `scale(0.95)` 和低透明度进入。Popover/Dropdown 应从触发源方向设置变换原点。按钮在按下时可提供短暂且克制的缩放反馈。为所有非必要动效尊重 `prefers-reduced-motion`，并让减少动态效果时的界面仍然完整可用。

## UI 状态必须真实

界面不能撒谎。Spinner 仅表示实际工作正在进行；成功只表示底层动作完成；草稿、暂存和乐观状态必须与已保存/已同步清楚区分；断开的 Agent、任务或服务不能显示为活跃。所有异步操作应提供适当的加载、失败、重试、取消或回退策略。

## 媒体与视觉证据

不要将大图片、视频或其他大媒体直接塞入 Web 构建目录。使用项目现有或用户确认的资产管理方法，将源素材置于构建目录外；不要将某个项目特有的存储路径、上传 CLI 或地图集成当作通用规则。

用户可见 UI 改动在可行时必须提供前后截图。若动效、时序、拖放或多步骤交互是重点，则用短录屏或等效的交互证据验证，而不是仅提供静态图。

## 交付前快速检查

在读取 `quality-gates.md` 前，先复核：实际背景下的文本可读性、主题变量成对关系、键盘路径、窄屏布局、导航逃生、加载/错误/空状态、减少动态效果、图片替代文本和界面状态诚实性。
