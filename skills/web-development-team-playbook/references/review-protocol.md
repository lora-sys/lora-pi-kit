# 严格零上下文对抗审查协议

每轮 Web 实现或修复完成后**必须**读取并执行本协议。此审查的目的不是复述实现意图，而是在不被需求与开发叙事影响的条件下，主动寻找当前代码和运行产物会失败、误导、不可用或退化的反例。

## 隔离边界

创建一个与主执行流程隔离的审查实例。它从零上下文开始，且不得接收、读取或被摘要告知以下信息：

- 用户原始需求、验收要求、聊天记录或主上下文；
- 任何开发计划、设计说明、架构说明、实现说明、变更摘要或预期结果；
- Git 历史、提交信息、Pull Request、Issue、研究笔记或此前审查结论；
- 既有测试、测试快照、测试报告或测试代码；
- 任何能让审查者反推原始目标的口头提示。

审查者只能接触：**当前待审代码快照**、实际可运行的当前产物（如可安全启动）以及项目本身为运行所必需的最小配置。不要额外解释文件、推荐检查区域或告诉它“应该是怎样”。若既有测试与运行环境不可分离，优先在隔离副本中排除测试目录、测试配置和历史元数据，而不是让审查者读取它们。

> 审查者的任务是观察“当前产物实际上做了什么”，不是判断它是否符合一个未告知的产品愿景。

## 审查步骤

1. **建立独立观察。** 仅从当前代码结构和可运行界面推断可见行为、状态和风险面；不索取原始需求。
2. **寻找反例。** 从输入、状态、数据、网络、权限、渲染、设备、可访问性和视觉层面，主动构造会造成错误、卡死、欺骗性状态、不可达操作或回归的条件。
3. **检查高风险维度。** 重点检查下表的维度；不因某个维度看似不相关而草率跳过。
4. **记录事实而非意见。** 每条问题必须含可复现步骤或静态证据、用户/系统影响、建议和置信度。没有证据的猜测应明确标为低置信度假设。
5. **压缩回流。** 主流程只接收问题清单的压缩摘要，不接收完整审查叙事或审查者的无关推理。
6. **独立核验。** 主流程针对每项发现，以源代码和运行事实验证真伪。真实问题修复后重新执行受影响质量门禁，再用隔离审查尝试复现或寻找回归。

## 强制审查维度

| 维度 | 对抗性问题示例 |
|---|---|
| 功能与边界状态 | 空数据、缺失字段、重复点击、快速切换、刷新、深链接、返回、取消和恢复后会发生什么？ |
| 状态诚实性 | Loading、Success、Saved、Active、Connected 等表述是否有底层事实支持？草稿或失败是否伪装为成功？ |
| 类型与外部输入 | 未知响应、无效 URL/参数、异常 JSON、缺失环境变量或 API 错误会否造成崩溃或不安全行为？ |
| 安全与隐私 | 是否意外暴露机密、信任未验证输入、执行危险渲染、绕过权限或混淆服务端/客户端边界？ |
| 可访问性 | 仅键盘能否完成可见任务？焦点是否可见且被困在正确区域？名称、标签、错误和动态状态是否可理解？ |
| 响应式与视觉 | 窄屏、宽屏、长文字、低对比图片、滚动背景、缩放、减少动效时是否破坏布局或可读性？ |
| 性能与可靠性 | 是否发生无意义重复请求、渲染循环、长列表卡顿、资源泄漏、无上限重试、阻塞交互或大资源阻塞？ |
| 路由与导航 | 直接访问、刷新、错误页、详情页和嵌套流程是否有可理解路径与安全回退？ |
| 回归风险 | 最小修复是否误改了共享状态、公共组件、主题、查询键或全局布局？ |

## 报告格式

审查实例每条发现使用以下格式。没有发现时，也必须说明检查范围和运行限制；不得简单写“看起来没问题”。

```markdown
### R-01 — 简短问题标题

- **置信度：** 高 / 中 / 低
- **证据：** 可复现步骤、当前行为、相关文件位置或运行观察。
- **影响：** 对用户、数据、安全、性能或可访问性的具体后果。
- **建议：** 最小、可验证的修复方向；不要引入无关重构。
```

回流主上下文时，仅保留：编号、问题摘要、证据的最小必要片段、置信度、主流程核验结果、是否修复以及复验结果。审查过程、需求猜测和冗余叙事均不回流。

## 主流程的核验规则

将审查发现当作需要核对的主张，而不是命令：

- 若发现真实，修复根因并重新执行受影响检查；不要只改表面文案或增加抑制规则。
- 若发现误报，保留简洁反证，例如相关代码路径、运行日志或受控复现结果；不要为满足自动化审查而修改正确代码。
- 若无法核验，说明具体阻塞，例如缺失凭据、第三方环境或无可运行产物；不得把未验证判断为已修复。
- 修复不应扩展成相邻功能重构；将额外机会单独记录。

## 禁止事项

- 不要向审查者泄露原始需求或“这次改了什么”。
- 不要让审查者阅读 Git 历史或既有测试来推断正确答案。
- 不要仅通过代码风格、命名偏好或假设的产品功能给出高优先级问题。
- 不要为审查者创建、推送或合并 Pull Request。
- 不要省略隔离审查，即使主流程已经运行了测试或收到其他机器人评论。
